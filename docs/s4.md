# S4 実機観察によるS2改訂 v1

配信PCで、撮影時のS2に対するS3の回答を照合し、既存ビューアで読める改訂版の `S2/bindings.json` と `S2/model.glb` を作る。機種共通の判定指示は[固定プロンプト](../generation/s4.md)に置く。

1. **入力を固定する。** `python -m tools.s4 prepare <機器フォルダー>` を実行する。対象を絞る場合は `--capture <撮影ID>` を繰り返す。PDF・S1・元S2・選択したS3原本とメタデータ、プロンプト・手順・実装のSHA-256を記録する。同じ機器で新しい撮影が増えても、既存回は当初のIDを使う。
2. **観察を記録する。** 出力された `prompt.md` に従い、レビュー担当者が原本と初版・説明書を照合して `review-template.json` のコピーを埋める。写真の領域は左上を原点とする0〜1の矩形、動画は開始・終了秒で示す。一つの撮影への回答を属性別に分け、各項目に初版・観察・判定を書く。根拠不足は未確定とし、描画の便宜で選んだ値は実測値と区別する。撮影そのものを外部APIに送る処理はない。
3. **修正を適用する。** `python -m tools.s4 apply <回のフォルダー> <レビューJSON>` を実行する。物理的な編集は `revise` の項目にだけ記す。公開先はレビューのハッシュごとに分ける。v1の局所編集は既存GLBの位置・回転・スケールのトラックの置換・追加、単独ノードの表示材質、既存部品・STEPの対応表を扱う。確認メモは元の項目に紐付けて残す・絞る・解決済みとして除く。未対応の編集は適用を中断する。
4. **同じ条件で比較する。** S1/S2の既存検査を両版に通し、全STEPのクリップを既存のThree.js再生処理で検査する。比較ページで同じ視点、同じ再生位置から変更STEPと共有クリップの参照先を確認する。原本のハッシュを再照合してから、改訂物・根拠・判定・検査結果を保存する。元S2の配信は継続する。

同じレビュー入力からの再生成は出力ハッシュで比較する。観察判断自体の再現性は、同じ固定入力を独立にレビューし、属性別の判定と根拠区間を突き合わせて評価する。1回の改訂で確認できるのは前者と個別の映像整合性まで。
## レビュー入力の書き方

配信PCのPython 3.11以降、PyAV、Node.js、既存のThree.jsを使う。依存の準備はプロジェクトの起動手順と共通。映像を解釈するのは固定プロンプトを読むレビュー担当者（Codexまたは人）。prepareは入力の固定、applyは判断済みの修正の適用と再生検査を担当する。

テンプレートに担当者・モデル名を記入し、各撮影の行を属性の数だけ複製する。各行の `capture`、`seconds` または `region`、`property`、`baseline`、`observation`、`decision` を埋める。判定値は `confirmed`、`revise`、`unresolved`。説明書を照合した場合は `manual`、非実測の描画値には `displayChoice` を記録する。

| 編集 | edits配列の要素 |
| --- | --- |
| トラック | `op: track`、クリップ名 `clip`、ノード名 `node`、`path`（translation / rotation / scale）、元クリップの長さを0〜1とする時点列 `at`、各時点のノードローカルの絶対値 `values`。回転値はxyzwの単位クォータニオン。異なる種類のトラックを置換する場合は元のpathを `replace` に指定する。 |
| 材質 | `op: material`、`node`、線形色空間の0〜1の `rgba`。そのノードだけに適用する。 |
| 対応表 | `op: parts` または `steps`、既存の `id` と新しいS2レコード全体の `value`。 |

同じ確認メモに複数の判定があるときは、それらを読み合わせて `remainingNote` を1回指定する。英語の文字列なら残った問いに更新し、nullなら解決済みとして除く。省略は維持。元S2と回答の全履歴は残る。比較ページ `compare.html` はファイルとして開ける。実写は含まず、改訂前後のモデルと手順を内蔵する。
