# 配信PC・端末登録・会場デモ

配信PCで `./tools/Open-QuestCapture.ps1` を実行する。管理画面は [localhost](http://127.0.0.1:52393/)、端末用のHTTPSアドレスは起動時に表示される。PCと端末は相互通信できる同じネットワークに接続する。複数のネットワークがあるときは `-Address <PCのIPv4>`、USB転送には `-Usb` を使う。証明書の作成にはOpenSSLまたはGit for Windowsが必要。初回は起動時に表示される証明書のSHA-256指紋を照合する。

| 用途 | PCでの操作 | 端末に許可されること |
| --- | --- | --- |
| 個人 | 「自分の端末を登録」でQRを発行。端末に出た申請番号を照合して承認する | 参加者の資料、機器の登録、撮影・保存、任意のGemini相談 |
| 会場デモ | 「DEMOの参加QRを表示」。来場者は使う端末のブラウザで開く | DEMOの公開済み資料、撮影、自分の撮影記録の再生 |

両方のQRは2分有効。個人用は1回限り、DEMO用は有効時間中に複数端末が参加できる。再発行すると同じ種別の古い招待は失効する。登録済みブラウザは通常の端末用URLから再入場できる。Cookieを消した場合や別のブラウザを使う場合は再登録する。

## 端末の管理

管理画面に種別、名前、接続元IP、最終アクセスを表示する。端末名の変更・個別解除・DEMOの一括解除ができる。個人とDEMOの権限は独立しており、同じブラウザで両方使える。旧版で承認記録のない個人端末は、既存の申請をPCで一度承認する。登録情報の保存先は `.local/quest-wifi/pairing.sqlite3`。Cookieの期限は利用時から400日。解除後も端末に保存済みの資料は残る。

## DEMOの準備

配信PCで `python -m tools.prepare_demo <参加者ID>` を一度実行し、指定した参加者の完成済みPDF・手順・図・モデルを `.local/users/DEMO/` に複製する。研究室の配信PCでは6機種を用意済み。既存のDEMOがあると処理を中止する。個人の撮影原本は複製対象外。会場での撮影は1件64 MiB、同時3件、原本合計2 GiBまで。配信PCではすべてのDEMO撮影を確認できる。
