# Quest 3でのMR撮影

1. [個人端末としてQuestを登録](access.md)し、S2が完了した機器を用意する。
2. アプリの参加者IDを入力し、「MR撮影を開く」を押す。ボタンは没入型AR・カメラ取得に対応するブラウザで表示する。機種名による制限はない。機器の作業支援画面ではS2完了後に表示する。撮影可能な機器が複数あればMR内で選ぶ。
3. アイコンに人差し指を近づけると、小さな輪と操作名が出る。そのまま正面からタッチして選ぶ。離れた位置では指してピンチするか、コントローラーのトリガーで選ぶ。本のアイコンで手順原文・注意・図・確認メモを開ける。注意があると本に三角印が付く。承認済みの個人端末では「Gemini音声を使う」を選ぶと最初の依頼を自動で読み上げる。
4. ビデオまたはカメラのアイコンで外向きカメラを開く。パネルがプレビュー中心の小窓になり、動画は赤丸で録画、四角で停止・送信、写真は二重丸で撮影・送信する。動画は無音で最長60秒。動画の依頼でもカメラを選べば現況を写真で残せる。
5. 写真は保存後にその場で見直す。1枚で終了する、撮り直す、次の写真へ進む、動きの疑問だけ動画で確かめる、のいずれかを選べる。送信失敗時は同じ撮影を再送できる。未送信の記録はページを閉じると失われる。PCでは同じ参加者・機器の「実機の撮影記録」を開き、日時・媒体・STEPで写真表示または動画再生ができる。

## MRパネルの位置

- 初期位置は右下。手入力で初めて開くと目から約50 cmに置く。歩行や大きな方向転換にはゆっくり追従し、指をパネルに近づけると追従を一時停止する。撮影時は同じ位置でプレビューに縮む。パネル幅は手入力で36 cmから26 cm、コントローラーで52 cmから32 cm。
- 撮影と位置合わせのパネルは、四隅の水色の印を指でつまむか、コントローラーで指してトリガーを押しながら伸縮できる。反対の角を固定して縦横比を保つ。倍率は初期幅の65〜200%で、撮影・位置合わせ別に端末に保存する。
- 鍵を選ぶとその場に固定する。閉じた鍵を選ぶと、今の位置から追従を再開する。下端の持ち手を親指と人差し指でつまむと、上下・左右・奥行きに動かせる。指を開くと固定する。コントローラーでは持ち手をトリガーで押し続けるか、パネルを指してグリップを握る。
- 同じブラウザでは、最後に置いた位置を作業方向からの相対位置として記憶し、次のMR開始時にそこから追従する。見失ったときは、パネルの外を指してグリップを握ると右下の初期位置に戻る。
- アイコンの操作名は日英切替に対応し、撮影依頼と読み上げは日本語。[空間パネル操作](https://developers.meta.com/vr/design/hands-3d-best-practices/)・[HUD配置指針](https://developers.meta.com/vr/documentation/iwsdk/concepts/spatial-ui/hud/)
- 撮影と位置合わせは同じパネル操作と手表示を使う。Quest Browserで手の使用を許可すると、パネルの手前にある指の形だけが透明になり、パススルーの自分の手が見える。左右25関節で動く手モデルを深度マスクに使い、表面だけを外側に2 mm広げる。タッチと実機の位置記録には追跡した指先座標を使う。追跡が途切れた手のマスクは消える。[Metaの手の表示設計](https://developers.meta.com/vr/resources/hand-representation/)・[WebXR Hands](https://developers.meta.com/vr/documentation/web/webxr-hands/)
- 直接タッチと持ち手のピンチが成立した瞬間、接触位置に波紋が広がり、短いクリック音が1回鳴る。裸手への物理振動はない。クリック音は端末で再生し、撮影動画は従来どおり無音。手モデルは配信PCに同梱した `@webxr-input-profiles/assets` 1.0.20の `generic-hand` を使う。[手入力のフィードバック設計](https://developers.meta.com/vr/design/hands-ui-best-practices/)・[モデルのライセンス](../web/hands/LICENSE.md)

## 撮影依頼と音声の仕様

- S2メモにSTEP指定があればそのSTEPを使う。部品指定だけなら、部品のクリップとの一致と対象部品の一致から関連STEPを選び、説明書順に案内する。対応するSTEPがない部品は最後に部品図で示す。メモがない機器はS1のSTEPを使う。
- 研究室6機種の70件は、確認メモ原文に対応する日本語の構図と媒体を用意した。写真は対象部品を強調し、動画はSTEPにクリップがある場合に指定順に再生する。ほかのメモでは部品名・クリップから依頼文を組み立てる。保存形式はJPEG、WebM、MP4で、上限は1件64 MiB。
- Geminiを使う場合は、配信PCを起動する環境に `GEMINI_API_KEY` を設定する。既定モデルは `gemini-3.8-live`。変更する場合は音声出力対応のモデル名を `GEMINI_LIVE_MODEL` に指定し、配信PCのサーバーを再起動する。PC・QuestからGoogleへのインターネット接続が必要。
- 配信PCが読み上げ用と相談用の指示を分け、モデルと音声出力を固定した短期トークンを発行する。新規接続は1分以内・1回限り、利用期限は15分。QuestはWebSocketで接続し、返ったPCM音声を再生する。通常の読み上げは案内文のみを送る。「音声で相談」を開き送信を選ぶと、その質問中だけマイクを使う。「写真と声で質問」の場合のみ対象の実写1枚もGoogleに送る。Liveの回答は日本語の音声と文字で返す。Geminiを外した場合、通信失敗時、DEMOでは端末内の日本語音声を使い、対応音声がなければ文字で案内する。[短期トークンの公式仕様](https://ai.google.dev/gemini-api/docs/ephemeral-tokens)・[Live APIの通信仕様](https://ai.google.dev/api/live)

## 承認済みQuestで最初の1件を試す

1. Quest BrowserでいつものWi-Fi入口を再読み込みし、参加者 `LAB6-20261120` の「機器一覧を開く」から大判プリンター（PRO-6600）を選ぶ。
2. 「Gemini音声を使う」を選んだ状態で「MR撮影を開く」。最初は「電源を切る」STEP 1の状態確認。音声の案内に従い、現在のステータスランプにカメラを向ける。電源を操作する必要はない。
3. カメラのアイコンを選び、カメラを許可し、小窓の二重丸で写真を撮る。保存案内が出たらMRを終了し、配信PCで同じ機器の「実機の撮影記録」から写真を開く。動画を試す場合は、CD-SE50で最初の写真を保存し、「動きの疑問へ」→上ぶたの候補で「動きを確認」と進む。
