# PDFからの初版作成

「Add」でPDFを登録すると、元PDFを参加者別SQLiteに保存し、Codexで型番候補を抽出する。機器名・登録時の任意型番は手掛かりとして渡す。候補の掲載ページを表示し、「この型番で作成」で対象を確定する。候補が空なら手入力できる。既存の登録PDFは「作業支援を作成」から開始する。

## 作成順

全機器で同じ[英語の生成指示](../generation/)を使う。プロンプトは段階ごとに1ファイルを直接編集し、過去版はGit履歴で参照する。各段階の指示にJSONの出力例・項目の意味を記載し、受信後に配信PCで形式と参照を検査する。S1の原稿は説明書の原語、S2の表示部品名と確認メモは日本語とする。

配信PCがPopplerで取り出した本文とページ画像を、ログイン済みのCodex CLIへ段階ごとに送る。図の切り抜きとGLBの組立は配信PCで行う。生成にはネットワーク接続が必要で、配信PCでは1件ずつ処理する。

S2の形状・組付け・可動支点の指示には、旧版と同じ [machine-skill の固定版](https://github.com/AirsupHQ/machine-skill/tree/e0bd066ac5beaf48512935de2fc0f0e55636853a)を参照した。原本のローカル保存先は `.local/skills/machine-skill/`。生成時はS2の固定指示とWeb版のGLB組立処理を使う。

1. 型番確定後、S1が共通手順と選択型番の手順・図を抽出する。作業順、原文、安全上の条件、出典を保持する。
2. S1の検査が通ったら自動でS2に進む。作業・手順IDは固定する。S2はPDF・S1から初版GLBと対応表を作り、全Stepと部品・クリップの参照を検査して公開する。
3. PCの支援画面で作業と手順を選ぶ。対象があれば部品を強調し、部品名パネルと指示線を表示する。クリップがあれば順に再生する。対象が空なら原文と図で案内する。複数の図は1枚ずつ切り替える。

生成中にブラウザを閉じてもサーバーで続行する。サーバー再起動後は支援画面を開くと未完の段階から再開する。生成・検査に失敗した場合は同じ段階を再試行できる。生成物の検査は形式と参照の確認で、モデルの形状・動作と実物との一致は別途確認が必要。

## 保存する成果物

元PDF・選択型番・進捗はSQLiteに保存する。公開先はそのDBと同じ場所の `devices/<参加者の世代ID>/<型番>-<取込ID>/`。フォルダ名の型番は英数字等に正規化する。取込IDで同じ型番の別登録を区別する。

| 成果物 | 内容 |
| --- | --- |
| `S1/task_step.json` | 元PDF ID、型番、原文言語、部品図の一覧、TaskとStep。タイトルと本文は言語別で併記時は英語優先。出典はPDF先頭を1とする。訳があれば日本語表示に使う。 |
| `S1/figure/` | 図の切り抜きPNG。ファイル名がID。手順図と部品図に同じ画像を再利用でき、各一覧は空でもよい。 |
| `S2/model.glb` | 個々の対象部品を指せるノードと、PDFで裏付けられた動作クリップを持つ初版。 |
| `S2/bindings.json` | `parts` に部品ID・名称・ノード名・図上の位置・動作。部品図に載っている未参照部品も制作対象。`steps` は全Step IDに `target_part` と `clips` の2項目。`notes` は実物で確認したい部品または手順への短いメモ。 |

S2までで初版を使用できる。S3の撮影依頼とS4の動画による改訂は未実装。S4はS2と同じ成果物形式・部品ID・手順IDを使う設計。Quest上での実機の部屋配置と、部品単位の局所補正も今後の対象。
